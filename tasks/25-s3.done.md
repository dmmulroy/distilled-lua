## What was built

- `providers/s3.lua` and `clients/s3/` (generated, committed): `require("s3")`, all 112
  operations of `@distilled.cloud/s3` (`dl parity`: s3 112/112). The model is
  `models/aws/s3.json` (Distilled has no S3 convert script: `packages/aws/scripts/convert.ts`
  + `patches/s3/` write it, `packages/aws/scripts/generate.ts` turns it into
  `packages/s3/src/services/s3.ts`). Generation and runtime are task 17's AWS support

  credentials/region/endpoint/clock, and `s3.presign_request(client, op, input, opts)`

  checksums, the rest returned as headers to send, bodies refused).
- `lua/distilled/s3/checksum.lua` (httpChecksum middleware) and
  `lua/distilled/s3/payload.lua` (x-amz-content-sha256 / UNSIGNED-PAYLOAD rules): ports of

  protocol has the same rules inline).
- Conformance against the TypeScript package (`verify/lib/s3_conform.mjs` ->
  `spec/golden/s3/conform.lua`, replayed by `spec/s3_conform_spec.lua` on all runtimes):
  47 signed requests (method, URL, every header including the SigV4 Authorization, body:
  virtual/path addressing, dotted/uppercase/short buckets, region input, cn partition,
  session token, MinIO/R2 endpoints, greedy keys, label refusals, PutObject metadata and
  checksums, ListObjectsV2 query, DeleteObjects/CreateBucket/PutBucket* XML + Content-MD5,

## Skipped, and why

- `dl gen-diff s3` / `gen-all s3`: they look for `models/s3/`, and S3's model is
  `models/aws/s3.json` (verify/dl is not mine; proposal in STATUS). Its steps were run by
  hand above (generate with lua and luajit, diff, stylua, gen_check on three runtimes).
- Live S3 / MinIO: no network in tests; the HTTP spec uses the local fixture server.
- Not ported (Distilled has them, Lua cannot or does not yet): streaming bodies and
  aws-chunked uploads (bodies are whole strings), event streams (SelectObjectContent),
  SigV4A (Multi-Region Access Points, fails with SdkError). S3 Express session auth is
  not in Distilled either.

## Open problems (task 17's runtime; details and fixes in STATUS.md "25 s3")

- GetObject: a body that is valid base64 is base64-decoded (`decode_success` ignores
  `read.raw` in its `by_name` branch). The most serious one: binary downloads can be
  corrupted. Empty bodies are dropped both ways.
- GetBucketLocation returns `{}` (unwrapped-output flag on the op, read on the shape).
- S3 error classes have no status-derived categories.
- A missing required label is sent instead of failing with ParseError.
- `parse_tag = "ParseError"` collides with the model's ParseError shape.
- Intended differences (kept): custom endpoint trailing "/", CRC32C/SHA1/SHA256 computed,
  no default `text/plain` content-type, user-agent, empty-message rule, POST field order
  of a map (`verify/features/s3.md`).
- Merge order: this branch carries task 17's commits up to 8768002.

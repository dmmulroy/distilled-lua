### Read this before writing code (gopher-lua facts, measured in Rex)

- **Never use plain `pcall` in library code.** In gopher-lua a `pcall` that catches an
  error breaks the upvalues of closures created earlier in any running frame (they keep
  writing to a stale copy). `compat.pcall(fn, ...)` is built on `xpcall` and is safe. In
  specs use `t.pcall(fn)`. This bug made `spec/run.lua` print `ok` after a failure before
  it was fixed (counters now live in a table).
- `error(msg, 2)` reports at level 1 in gopher-lua. Use `compat.raise(msg, 2)` when the
  position matters (`distilled.check` does).
- `table.concat` raises "registry overflow" past ~2,500 items: use `compat.concat`.
- Call stack ~250 frames: no recursion over data depth (json and `secret.unwrap_deep` use
  explicit stacks). `t.same` recurses, so compare very deep data by encoded string.
- `math.huge` is the largest finite double; use `1/0` for infinity.
- `tonumber` rejects `"1e5"`, big digit strings and out-of-range numbers (nil); use
  `json.decode` for wire numbers.
- Weak tables are never collected. `string.format("%s", t)` ignores `__tostring`.
- `rex do` script: `debug.getinfo(1, "S").source` is the absolute path (no `@`);
  `rex.args` holds `key=value` arguments; `error(...)` exits 1 with `Error: <msg>`;
  `os.exit(n)` works too; `print` goes to stdout.

### Decisions others should know

- `verify/dl` is POSIX `sh`: it must work before any Lua does (doctor, manifest), it only
  glues interpreters and files together, and heavier logic lives in `verify/lib/*.lua`.
- Spec discovery: `spec/manifest.lua` is generated by `verify/dl manifest` (and by
  `dl test` when stale); `dl doctor` fails when it is stale. **Commit the regenerated
  manifest together with a new spec file.** It is deterministic, so concurrent agents
  produce the same content.
- Harness additions beyond the contract: `t.ne`, `t.no_match`, `t.raises(fn, pattern)`,
  `t.fails_with(tag, f(...))` (tag first, so a call's two results pass straight in;
  `t.err(f(), nil, tag)` does NOT work, Lua truncates `f()` to one value), `t.fail`,
  `t.pending`, `t.show`, `t.pcall`, `t.root` (repo root, for fixtures).
- `dl test --json-fuzz` is the Node differential check; `dl json-bench` times the codec.

### Deviations from / additions to `docs/interfaces.md` (proposed contract updates)

- `compat` also has `pcall`, `raise`, `concat`, `normalize_number`, `is_integer_subtype`,
  `ERROR_LEVEL_SHIFT`.
- `json` also has `json.is_object`, `json.MAX_DEPTH` (1000, counts every container).
  Decode errors are `ParseError` with `err.position` (byte offset) and line/column in the
  message; encode errors are `InvalidInput`. `-0` encodes as `0` and numbers format like
  `JSON.stringify`. Lone surrogates decode to U+FFFD. On 5.5 integral numbers below 2^53
  decode as integers. `json.encode` refuses secrets.
- `errors.match`: a matched error's `code` is the wire code or `nil` (Distilled: `0`).
  Instance field names (`status`, `code`, `message`, `body`, `headers`, `retry_after`,
  ...) are reserved: a class field with such a name is not filled from the body.
  `response_info` also accepts `errors = { { code, message }, ... }` (several wire errors)
  and `retry_after` (seconds, parsed by the caller; set only on classes declaring the
  `retry_after` field). With no code and no message the wire message is `HTTP <status>`.
  The regex hook for `matches` is the local `regex_test` in `errors.lua` (returns false
  until task 03).
- `errors` also has `errors.classes[tag]` and `errors.<Tag>` for built-ins, `is_class`,
  `at_pointer`, `matches_expression`, `matcher_specificity`, `RETRYABLE_STATUSES`,
  `DEFAULT_STATUSES`. `errors.new` with an unknown tag string makes a category-less class;
  `message` defaults to `HTTP <status>` or the tag. `InvalidInput` declares `member`,
  `ConfigError` declares `key`.
- `distilled.secret` is the secret module and is callable (`distilled.secret(v)` wraps).
  `distilled.scope(fn)` is `Scope.with`; `distilled.Scope`, `distilled.json`,
  `distilled.errors` are exported too.
- `scope:defer` on a closed scope runs the finalizer at once.

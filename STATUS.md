### Read this before writing code (gopher-lua facts, measured in Rex)

- **Never use plain `pcall` in library code.** In gopher-lua a `pcall` that catches an
  error breaks the upvalues of closures created earlier in any running frame (they keep
  writing to a stale copy). `compat.pcall(fn, ...)` is built on `xpcall` and is safe. In
  specs use `t.pcall(fn)`. This bug made `spec/run.lua` print `ok` after a failure before
  it was fixed (counters now live in a table).
- `error(msg, 2)` reports at level 1 in gopher-lua. Use `compat.raise(msg, 2)` when the
  position matters (`distilled.check` does).
- `table.concat` raises "registry overflow" past ~2,500 items: use `compat.concat`.
- Call stack ~250 frames: no recursion over data depth (json and `secret.unwrap_deep` use
  explicit stacks). `t.same` recurses, so compare very deep data by encoded string.
- `math.huge` is the largest finite double; use `1/0` for infinity.
- `tonumber` rejects `"1e5"`, big digit strings and out-of-range numbers (nil); use
  `json.decode` for wire numbers.
- Weak tables are never collected. `string.format("%s", t)` ignores `__tostring`.
- `rex do` script: `debug.getinfo(1, "S").source` is the absolute path (no `@`);
  `rex.args` holds `key=value` arguments; `error(...)` exits 1 with `Error: <msg>`;
  `os.exit(n)` works too; `print` goes to stdout.

### Read this before writing code

- **A second gopher-lua upvalue bug: nested protected calls.** Once a `pcall` or `xpcall`
  has *completed* inside another protected call, the outer one catching an error breaks
  the upvalues of closures in running frames, exactly like the plain-pcall bug. So
  `compat.pcall` (xpcall) is **not** safe when nested: `xpcall(function() xpcall(f, h);
  error("y") end, h)` leaves a counter closure writing to a stale copy (measured in Rex,
  `/tmp`-style repros in the done file). A coroutine that catches the error is not
  affected. **Fixed in the follow-up:** `compat.pcall` is now built on a coroutine.

### Follow-up (after verification)

**Done.** `compat.pcall` is rebuilt on a coroutine (same signature, same results); the
tracer, `Scope` and the harness all go through it; the noop tracer is its own module.

- **`compat.pcall(fn, ...)`** runs fn in a coroutine. It is safe from both gopher-lua
  upvalue bugs at any nesting depth, and yield-transparent: a yield inside fn goes to the
  coroutine that called compat.pcall and the resume values come back. Outside any
  coroutine a yield returns `false, "attempt to yield from outside a coroutine"`. When
  nested, the yield travels out to the outermost compat.pcall, which reports it (native
  `pcall(pcall, coroutine.yield)` would have the innermost one catch it instead).
  It accepts C functions and callable tables. The `ERROR_LEVEL_SHIFT` probe now runs in a
  coroutine too.
- **Limit (all runtimes, not caused by compat.pcall):** a yield cannot cross a C/Go call
  boundary such as a `table.sort` comparator or a `string.gsub` callback. lua/luajit
  raise "attempt to yield across a C-call boundary". **gopher-lua crashes the whole run**
  ("invalid memory address or nil pointer dereference"), with or without compat.pcall.
- **Changed behaviour others may notice:** code under compat.pcall sees a different
  `coroutine.running()`. A raise keeps its message and position, but a traceback taken
  later only covers the stack from the re-raise.
  `debug.traceback` must not be called through compat.pcall (that would trace the
  coroutine's stack); the harness now calls it directly in its handler.
- `Scope.with`, `scope:close` and `scope:defer` needed no change (they already call
  compat.pcall). The harness `t.pcall` / `t.raises` / `t.describe` use compat.pcall.
  `t._run` keeps one outermost `xpcall` for its traceback handler, which is safe because
  nothing nested inside it uses xpcall.
- `lua/distilled/trace/noop.lua` requires nothing. `distilled.trace` re-exports it
  (`trace.noop` is the same object, `trace.NOOP_SPAN`). A spec checks that requiring it
  loads only that module.
- Regression specs in `spec/compat_spec.lua` (11 new). With the old xpcall-based
  compat.pcall swapped back in, 9 of them fail under Rex.
- `verify/features/README.md` lists tracing.md and both bugs, plus the yield crash;
  `verify/features/scope.md` is updated.

### Client.define (what the generator emits)

```lua
local Client = require("distilled.client")
local rest = require("distilled.protocol.rest")
return Client.define{
  service = service,            -- docs/interfaces.md service descriptor
  protocol = rest.new{
    base_url = function(creds, route) return creds.base_url end,  -- or a string
    headers = rest.bearer("api_key"),   -- fn(creds) -> { authorization = "Bearer <key>" }
    unknown_tag = "UnknownNeonError", parse_tag = "NeonParseError",
    -- optional: error_envelope, error_fields_at, status_map, classify_error,
    -- transform_response, map_member_header, unknown_key_to_wire, empty_json_body,
    -- query_style, user_agent
  },
  options = {                   -- provider options: the user passes them to .new{}
    api_key = { secret = true, env = "NEON_API_KEY", required = true },
    base_url = { default = "https://console.neon.tech/api/v2" },
  },
}
```

- `options[name]` fields: `secret` (value is a string, a secret, or `fn(host) -> value |
  nil, err`; held as a secret; refreshable), `env` (read through `host.getenv` when the
  user gives no value), `default`, `required`, `type` (`"string" | "number" | "boolean" |
  "table"`, checked in `new`). Provider options cannot reuse a common option name
  (below); `define` raises.
- `creds` (what `base_url` / `headers` receive) is `{ [option] = value }` for every provider
  option: secret options as secrets (unwrap with `secret.unwrap` where the header is built;
  `rest.bearer(name)` and `rest.header(header_name, option_name)` do that).
  A missing required option fails the call with `ConfigError` (`err.key = name`), it does
  not raise in `new`.
- Methods come from `service.ops` keys: `client:get_project(input)`, and for an op with
  `pagination`: `client:list_projects_pages(input)` / `client:list_projects_items(input)`.
  `define` raises when an op name collides with `with`, `close` or another op's `_pages` /
  `_items` name.

### Common options of `Class.new{}` / `client:with{}`

`host`, and the host fields at top level (`transport`, `sleep`, `now`, `exec`, `random`,
`getenv`, `epoch`; top level wins over `host`), `retry`, `deadline_s`, `tracing`, `tracer`,
`trace_parent`, `validation` (`"lenient"` default, `"additional"`, `"strict"`), `budget`,
`server_hint_cap_s`, `user_agent`. Unknown names raise, listing the valid ones.

- `retry`: a preset (`retry.DEFAULT`, `THROTTLING`, `TRANSIENT`, `NONE`, or the strings
  `"default" | "throttling" | "transient" | "none"`) or a table of policy fields merged
  over the default (`{ max_retries = 5 }`); `retry = { deadline_s = 20 }` sets only the
  deadline. `deadline_s` at top level is the same thing.
- `tracing`: `"off"` (default) | `"operation"` | `"debug"` | `{ level, file, max_bytes,
  exporter }`. A string level without an exporter writes the console tree to
  `io.stderr`. `tracer = <tracer>` installs an existing tracer (tests, `dl trace`).
- No transport is a `ConfigError` at call time (`err.key = "transport"`). Default `sleep`
  is a busy wait on `os.clock` (no sleep in pure Lua): hosts should pass one.

### Protocol seam (`protocol.call(ctx, op, input) -> value | nil, err, meta`)

`ctx = { service, op_name, credentials = fn() -> creds | nil, err, host, tracer, span,
validation, timeout, attempt }`. `span` is the operation span (or the no-op span);
`timeout` is the remaining deadline in seconds (copied to `request.timeout`); `attempt` is
the retry loop's table, where the protocol records `host` (the request's host),
`status` and `hint_ms` (bounded hint). **Third return value `meta = { status, headers }`**
whenever a response arrived (success or failure): this is how `link` pagination gets the
`Link` header, with no global.

### Errors the runtime adds

- `<unknown_tag>` (no category, never retryable; `status, code, message, body, headers`)
  and `<parse_tag>` (category `ParseError`; `body`, `cause`).
- A raise inside a user callback (credential function, `classify_error`,
  `error_envelope`, `transform_response`, retry `when`) becomes `SdkError` with the
  message and `err.cause`.
- With tracing on, a failed call's `err.trace_id` is set.

### Follow-up: tracer attach/detach (done)

- `tracer:detach(span) -> true|false`: takes the innermost open span off the active stack
  and keeps it open, so later spans are not its children.
- `tracer:attach(span) -> true|false`: makes a detached open span current again.
- Both return false, and change nothing, for the no-op span, a finished span, a span not
  innermost (detach), or a span already on the stack (attach). Attaching another
  tracer's span raises. `trace.noop` has both; they return false.
- `paginate.lua` uses them, and falls back gracefully for a tracer without them.
  `docs/interfaces.md` should list them (orchestrator).

### Decisions others should know (the generated service data)

- `op.span` and `service.telemetry` are Distilled's compressed form (`codegen/generator.ts`
  `telemetryLines` / `TELEMETRY`, read by core `telemetry.ts` `operationInfo`), keys in
  snake_case: `service.telemetry = { system, response_headers = { { header, name,
  transform } }, prefix = "Neon", service = "Neon", labels = "neon", label_names,
  attributes, templates = false|nil, propagate = "w3c" }`; `op.span` is the op's model
  name (`"GetProject"`) when everything else derives, else `{ op, name, method, kind,
  template = false, attributes, input = { [member] = { rules } }, output }`. A label
  member without an attribute rule gets `input = { key = {} }` (drops the derived one),
  as Distilled emits `key: []`. `--no-telemetry` emits neither. (Task 04's
  `operation.lua` reads exactly this.)
- `op.retry` keys are snake_case of `distilled.retry#policy` (`max_attempts`, `base_ms`,
  `throttling_base_ms`, `cap_ms`, `factor`, `long_poll`). Neon has none.
- Generated error classes follow Distilled's `errorCategories` exactly: Neon's `NotFound`
  (404) gets `BadRequestError`, not `NotFoundError` (the core built-in keeps it). Error
  shapes with no members get no `fields` (code and message are instance fields).
- Member tables are plain data with false flags omitted and `bind` omitted for body.
  Named shapes are registry entries keyed by local name; every reference is `S.ref`.
  A rawResponse output is the member's node with `output_raw = true` (Blob: `S.blob`).
- Lazy shapes were not needed: the full Neon service loads in about 2 ms / 600 KB
  (lua, luajit) and 23 ms in Rex; a 3-operation `--ops` client in 0.3 ms / 1.2 ms.
- Provider spec additions: `allow_unsupported = { "multipart" }` (without it a multipart
  operation fails generation); `status_map` names tags, and the generated `init.lua`
  copies `errors.STATUS_MAP` and sets the entries (rest.new takes classes and replaces
  the whole map); `classify_error` / `protocol` are module names (functions cannot be
  written into generated code).
- The generator has its own ordered JSON decoder (`gen/json_ordered.lua`): Smithy member
  order matters and `distilled.json` cannot carry it.
